Rechtlicher Hintergrund

Seit dem 28. Juni 2025 verpflichtet das Barrierefreiheitsstärkungsgesetz (BFSG) fast alle B2C-Anbieter zu digitaler Barrierefreiheit. Grundlage ist die EU-Richtlinie (EU) 2019/882 (European Accessibility Act, EAA), technisch umgesetzt über EN 301 549 — die wiederum auf WCAG 2.2 AA verweist.

Ein Widget ersetzt keinen sauberen Code. Aber eine gut implementierte Präferenz-Ebene (Kontrast, Schriftgröße, Fokusrahmen, TTS) ist ein echter Gewinn für Nutzer:innen — und ein sichtbares Bekenntnis des Betreibers.

Integration

Ein <script>-Tag reicht. Für Frameworks und CMS/Shop-Systeme gibt es fertige Wrapper. 

<script
  src="https://cdn.example.com/accessibility-widget/accessibility-widget-loader.min.js"
  defer
></script>
import { AccessibilityWidget } from '@bauer-group/accessibility-widget-react';

export default function Layout({ children }) {
  return (
    <>
      {children}
      <AccessibilityWidget
        loaderSrc="/accessibility-widget/accessibility-widget-loader.min.js"
        cssHref="/accessibility-widget/accessibility-widget.min.css"
        config={{ locale: 'auto', primaryColor: '#0058a3' }}
      />
    </>
  );
}
<script setup lang="ts">
import { AccessibilityWidget } from '@bauer-group/accessibility-widget-vue';
</script>

<template>
  <AccessibilityWidget
    loader-src="/accessibility-widget/accessibility-widget-loader.min.js"
    css-href="/accessibility-widget/accessibility-widget.min.css"
    :config="{ locale: 'auto' }"
  />
</template>
# 1. Plugin-Ordner nach wp-content/plugins/
cp -r integrations/cms/wordpress/accessibility-widget \

cp packages/widget/dist/accessibility-widget-*.min.{js,css} \
   wp-content/plugins/accessibility-widget/assets/

# 3. Im WP-Admin: Plugins → aktivieren → Einstellungen → Accessibility Widget
{%- comment -%} Im theme.liquid {%- endcomment -%}
{% render 'accessibility-widget',

   locale: 'auto',
